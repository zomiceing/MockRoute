# 跑步模拟使用说明

配套阅读：[06-步行模拟](06-步行模拟.md)（GPS 噪声原理那节对跑步同样适用，本文不重复）。

跑步不是"把步行调快"。真实的跑步轨迹有三个步行没有的特征：

1. **配速在变** —— 跑者每段配速都不一样（体能、路况、红绿灯、疲劳），
   分段配速标准差约为平均配速的 8%~15%；步行几乎是恒速的。
2. **海拔影响配速** —— 上坡明显变慢，这是跑者最在意的变量（"爬升"）。
3. **加减速更猛** —— 起步/停步的加速度比走路大 3~4 倍。

这三条都实现了。

---

## 一、30 秒跑起来

```powershell
# 1) 生成跑步轨迹（真实路网 + 配速波动 + 合成地形 + 坡度效应）
python tools\mroute.py gen --preset run `
    --from 39.90870,116.39750 `
    --to   39.88220,116.40660 `
    --provider osrm --profile foot `
    --seed 42 --out out\run5k.json

# 2) 看图：路线形状 + 沿程海拔 + 配速曲线
python tools\plot-route.py out\run5k.json -o out\run5k.png

# 3) 推到手机开始跑
powershell -ExecutionPolicy Bypass -File scripts\mroute.ps1 play --route out\run5k.json
```

![跑步轨迹示例](../out/run5k.png)

上图是一段 4.5 公里的跑步模拟：右上角小图是**沿程剖面** —— 灰色填充是海拔（地形起伏），
黄线是配速，能直接看出"上坡段配速下降"。

## 二、三个预设

| 预设 | 速度 | 配速 | 配速波动 | 地形 | 适用 |
| --- | --- | --- | --- | --- | --- |
| `--preset walk` | 1.35 m/s | 12'20"/km | 5% | 无 | 步行 |
| `--preset run` | 3.3 m/s | **5'03"/km** | **12%** | ±8m，坡度生效 | 日常跑步 |
| `--preset interval` | 3.6 m/s | 4'38"/km | **38%** | ±8m，坡度生效 | 间歇训练 |

预设是**叠加**的：`run` 包含 `walk` 的全部基础调整（细采样、低噪声），
再加上跑步特有的部分；`interval` 再在 `run` 之上加大配速波动。

### `--preset run` 的具体值

| 参数 | walk | **run** | 为什么 |
| --- | --- | --- | --- |
| `--speed` | 1.35 | **3.3** | ≈5'03"/km，业余跑者常见配速 |
| `--interval` | 500 | **1000** | 与真实运动手表一致（1Hz） |
| `--accel` | 0.22 | **0.9** | 跑步加减速比走路猛 3~4 倍 |
| `--noise` | 2.0 | **1.8** | 手表/臂带天空视野更好，且多有 A-GPS |
| `--acc-mean` | 6.0 | **4.5** | 运动手表通常上报 3~6m |
| `--pace-variation` | 0.05 | **0.12** | 跑者分段配速标准差 8%~15% |
| `--pace-period` | 240 | **180** | 配速起伏的特征波长（米） |
| `--alt-amplitude` | 0 | **8.0** | 合成地形起伏 ±8m |
| `--grade-effect` | 关 | **开** | 上坡自动变慢 |

显式传的参数不会被覆盖：

```powershell
# 快跑（4'00"/km），地形起伏更大
python tools\mroute.py gen --preset run --speed 4.2 --alt-amplitude 15 `
    --from ... --to ... --out out\tempo.json
```

## 三、配速波动（跑步的核心特征）

### 3.1 模型

用**多个不同波长的正弦叠加**（不是随机游走）：

```
倍率(s) = 1 + amp × [0.55·sin(2πs/w1 + φ1) + 0.30·sin(2πs/w2 + φ2) + 0.15·sin(2πs/w3 + φ3)]
w1 = max(120, period)      w2 = max(120, 2.3·period)      w3 = max(120, 5.7·period)
```

为什么用正弦而不是随机游走：正弦曲线**天然光滑**，而且完全可复现（给定 seed）。
随机游走会产生突兀的加速，跑者身体做不到。

**波长下限 120 米是物理约束**：跑者无法在几十米内改变配速。
以 a=1.2 m/s²、v=3.3 m/s 计，配速变化率上限约 `a/v = 0.36 /m`。
早期版本用 `period/5.7`（180m 时只有 32m 波长），生成了物理上不可能的快速抖动。

### 3.2 怎么调

| 目标 | 参数 |
| --- | --- |
| 匀速跑（比赛配速） | `--pace-variation 0.05` |
| 日常跑步（默认） | `--pace-variation 0.12` |
| 明显的快慢交替 | `--pace-variation 0.25 --pace-period 400` |
| 间歇训练（快 400m + 慢 400m） | `--preset interval`（0.38 / 800m） |
| 完全匀速（算法回归测试用） | `--pace-variation 0` |

实测（2 公里，巡航段）：

| 配速波动 | 速度变异系数 CV |
| --- | --- |
| 0（关闭） | <1% |
| 0.12（日常跑） | 13% |
| 0.38（间歇） | 29% |

CV 与真实跑者的分段配速统计（8%~15%）吻合。

## 四、海拔与坡度

### 4.1 重要说明：这是合成地形

**OSRM 的演示服务器不返回海拔数据**，所以地形是本工具**自己生成的虚拟剖面**，
不是真实地形。生成的规则：

- 两个不同波长的正弦（长坡 + 短起伏）+ 低频随机漂移
- 波长用**绝对尺度**（300~1600m 的长坡、120~420m 的短起伏），不随路线长度缩放 ——
  真实地形的起伏尺度是固定的，跑 5km 和跑 21km 遇到的是同一类地形特征
- 坡度用 30 米窗口差分计算，天然滤掉高频抖动

实测（amplitude=8）：

| 路线长度 | 坡度中位 | 90 分位 | 最大 | 爬升 |
| --- | --- | --- | --- | --- |
| 500m | 7.0% | 15.9% | 17.8% | 43 m/km |
| 2 km | 2.6% | 5.1% | 5.9% | 14 m/km |
| 5 km | 2.4% | 5.1% | 5.9% | 13 m/km |
| 10 / 21 km | 2.4% | 5.1% | 5.9% | 13 m/km |

5km 以上稳定在 **2.4% 坡度中位、13 m/km 爬升** —— 典型的城市起伏路线。
短路线（500m）因为波长下限的关系会显得陡一些。

### 4.2 坡度怎么影响配速

```
上坡：配速倍率 = 1 / (1 + 1.6 × 坡度)      （每 1% 坡度约慢 1.6%）
下坡：配速倍率 = 1 - 0.6 × |坡度|           （下坡的收益小于上坡的损失）
```

倍率被限制在 0.55 ~ 1.35 之间。下坡收益小于上坡损失，这符合跑者的真实体验
（"上坡一分钟，下坡还回来三十秒"）。

### 4.3 调地形

| 场景 | 参数 |
| --- | --- |
| 操场/沿江平路 | `--alt-amplitude 0`（或加 `--no-grade` 思路：不传 `--grade-effect`） |
| 城市起伏路（默认） | `--alt-amplitude 8` |
| 丘陵路线 | `--alt-amplitude 20` |
| 山地越野 | `--alt-amplitude 40` |
| 真实爬升数据 | **用带 `<ele>` 的 GPX 文件**（见 6.3），本工具的合成地形会被路线文件里的真实海拔覆盖思路取代 |

### 4.4 海拔高度噪声

上报的 `alt` 字段 = 合成地形 + 高度噪声。真实 GPS 的**高度误差约为水平误差的
1.5~3 倍**，而且同样是时间相关的慢漂移 —— 所以高度用**同一个 AR(1) 模型**，
只是标准差 ×1.8。

> ⚠️ **不要用逐点高度差累加算"累计爬升"。** 高度噪声会让它严重虚高：
> 实测 5km / 1400 点的轨迹会报出 **2552m** 的"累计爬升"（比路线本身还荒谬）。
> `show` 命令报的是**净爬升**（终点 − 起点）。要精确爬升请用真实 GPX。

## 五、配速与速度读数

### 5.1 换算

```
配速(秒/km) = 1000 / 速度(m/s)
速度(m/s)   = 1000 / 配速(秒/km)
```

| 配速 | 速度 | 参考 |
| --- | --- | --- |
| 3'00"/km | 5.56 m/s | 业余顶尖 |
| 4'00"/km | 4.17 m/s | 认真训练的跑者 |
| **5'03"/km** | **3.30 m/s** | **`--preset run` 默认** |
| 6'00"/km | 2.78 m/s | 有氧慢跑 |
| 7'00"/km | 2.38 m/s | 恢复跑 |
| 8'00"/km | 2.08 m/s | 初跑者 |

### 5.2 为什么速度读数会抖

跑步一步 3.3 米（1Hz 采样）而 GPS 噪声 1.8 米，信噪比约 1.8:1 —— 比步行好，
但仍有可见抖动。处理方式与步行一致：

- **`speed` 跟随噪声后的坐标**（`speed = 位移/时间`），保证「拿坐标反推速度」
  和 `speed` 字段一致 —— 这是目标 App 最常用的检测手段；
- **`bearing` 用路径方向**，不从噪声坐标反推（跑步时噪声仍会淹没有效方向）。

上图中黄色配速曲线做了 5 点滑动平均**仅为作图可读性**，
`run5k.json` 里的 `speed` 字段是原始值。

要更平滑的读数：`--noise 1.2` 或 `--interval 500`（点数翻倍）。

## 六、典型场景配方

### 6.1 日常 5 公里

```powershell
python tools\mroute.py gen --preset run `
    --from 39.90870,116.39750 --to 39.88220,116.40660 `
    --provider osrm --profile foot --seed 42 --out out\run5k.json
python tools\plot-route.py out\run5k.json -o out\run5k.png
scripts\mroute.ps1 play --route out\run5k.json --mult 10
```

### 6.2 间歇训练（400m 快 / 400m 慢）

```powershell
python tools\mroute.py gen --preset interval `
    --from 39.90870,116.39750 --to 39.88220,116.40660 `
    --provider osrm --profile foot --out out\intervals.json
```

等效配速在 4'38" ± 38% 之间摆动，约每 800m 一个完整周期。

### 6.3 沿真实轨迹跑（含真实爬升）

手机或运动手表导出的 GPX 自带 `<ele>` 真实海拔：

```powershell
python tools\mroute.py gen --preset run --provider file --file my-run.gpx `
    --speed 3.3 --alt-amplitude 0 --out out\myrun.json
```

> 注意：`--provider file` 目前只读取经纬度，GPX 的 `<ele>` **尚未解析**。
> 若需要真实海拔参与坡度计算，这是一个明确的待办项 —— 见文末"已知限制"。

### 6.4 长距离 LSD（20 公里，低强度）

```powershell
python tools\mroute.py gen --preset run --speed 2.5 --pace-variation 0.06 `
    --interval 1000 --alt-amplitude 10 `
    --from ... --to ... --out out\lsd.json
```

### 6.5 操场跑圈（恒定配速、无地形）

```powershell
# 用一个小闭环 + 循环模式
python tools\mroute.py gen --preset run --speed 3.5 --pace-variation 0.03 `
    --alt-amplitude 0 --provider file --file examples\route-loop.geojson `
    --mode loop --out out\track.json
scripts\mroute.ps1 play --route out\track.json --mode loop
```

### 6.6 可复现的回归测试

```powershell
python tools\mroute.py gen --preset run --noise 0 --pace-variation 0 `
    --alt-amplitude 0 --seed 12345 `
    --from ... --to ... --out out\regression.json
```

固定 seed + 关噪声 + 关配速波动 + 关地形 → 每次生成完全相同的轨迹。

## 七、参数速查（跑步相关）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--preset run` | — | 一键配好跑步参数（推荐起点） |
| `--preset interval` | — | 间歇训练 |
| `--speed` | 1.4 | 目标速度 m/s（平均配速） |
| `--interval` | 1000 | 采样间隔 ms；500 更平滑、点数翻倍 |
| `--accel` | 0.4 | 加速度上限 m/s²；跑步 0.9~1.5 |
| `--pace-variation` | 0 | 配速波动幅度；跑步 0.08~0.15 |
| `--pace-period` | 180 | 配速波动的特征波长（米）；间歇 400~800 |
| `--alt-amplitude` | 0 | 合成地形幅度（米）；需要坡度效应就 >0 |
| `--grade-effect` | 关 | 让坡度影响配速（上坡变慢） |
| `--alt-base` | 45 | 海拔基准值（米） |
| `--noise` | 0 | GPS 水平误差标准差（米）；跑步 1.5~2.5 |
| `--noise-alpha` | 0.99 | 误差时间相关性；不建议改 |
| `--acc-mean` | 8 | 上报 accuracy 均值（米）；运动手表 4~6 |
| `--lead-in` | 3 | 起步前原地漂移点数（刚锁星） |
| `--start-offset` | 0 | 从路径起点跳过多少米 |
| `--mode` | once | `once` / `loop` / `pingpong` |
| `--seed` | 无 | 固定后可复现 |

## 八、怎么判断跑步轨迹质量

`plot-route.py` 生成的图里看三件事：

1. **路线形状**贴着道路（有直角转弯正常，说明用的是真实路网）
2. **沿程剖面**：黄线（配速）应当在灰区（海拔）上升段明显走低 —— 那就是上坡变慢；
   如果黄线与海拔无关，说明 `--grade-effect` 没生效
3. **配速曲线**有起伏但不该有毛刺；毛刺说明配速波长太短或噪声过大

数值检查：

```powershell
python tools\mroute.py show --route out\run5k.json
```

摘要会给出：点数、时长、里程、**平均/移动段速度**、**波动百分比**、**配速**、
海拔范围、净爬升。

参考基线（4.5km，`--preset run`）：

```
点数=1400  时长=1399.0s  沿路径里程=4529m  直线距离=3247m
速度 平均=3.23  移动段均=3.24  波动=13%  最大=4.49  最小=0.00 m/s
配速 ≈ 5'08"/km
海拔 28~64m  净爬升 +0m
```

判断标准：
- **波动** 8%~15% 正常；<3% 太平（不像真人跑），>40% 除非是间歇训练
- **最大速度** 不应超过目标速度的 1.5 倍（噪声导致的例外见 5.2）
- **配速** 与 `--speed` 换算应基本一致（差 10% 以内是噪声的贡献）

自检：

```powershell
python -m unittest discover -s tests -t . -v
```

74 项测试，其中跑步相关 5 项：配速曲线的幅度与物理平滑性、地形坡度合理性、
坡度对配速的影响、run 预设确实覆盖了 walk 基础层、配速波动可见性。

## 九、已知限制

| 限制 | 说明 | 变通 |
| --- | --- | --- |
| `--provider file` 不解析 GPX 的 `<ele>` | 真实海拔未参与坡度计算 | 目前只能用 `--alt-amplitude` 合成；这是明确的待办 |
| OSRM 演示服务器不返回海拔 | 所以地形是合成的 | 自建 OSRM 或换用带海拔的规划服务 |
| OSRM 演示服务器的 `--profile foot` 会退回 driving | 演示服务器实际只提供 driving 轮廓 | 自建 OSRM，或高德 `--amap-mode walking`（需 key） |
| 「累计爬升」不可从 `alt` 逐点累加 | 高度噪声会把它放大数十倍 | 用 `show` 的净爬升，或用真实 GPX |
| 配速波动是确定性正弦叠加 | 不是真实的生理模型（没有心率/疲劳曲线） | 用 `--pace-variation` + `--pace-period` 手工拟合 |
