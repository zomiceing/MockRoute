# 02 · 快速开始

假设 [01-环境准备](01-环境准备.md) 已完成，`doctor` 报告无阻塞项。

## 第一步：先确认「单点定位」能动

不要一上来就跑长轨迹。先用最简单的命令确认整条链路是通的。

```powershell
python tools/mroute.py point --at 39.9075,116.3910
```

在手机上打开任意地图 App，看蓝点是否跳到该坐标（北京东城区一带）。

**动不了就停下**，去看 [04-排障](04-排障.md)。十有八九是 appops 没授权。

结束后停止模拟：

```powershell
python tools/mroute.py stop
```

## 第二步：生成一条行进轨迹

### 先说起点终点怎么写（四种方式）

`--from` 和 `--to` 不只是收经纬度，可以混用：

| 方式 | 写法 | 示例 | 需要联网 |
| --- | --- | --- | --- |
| **经纬度** | `纬度,经度` | `--from 39.9087,116.3975` | 否 |
| **命名地点** | 名字 | `--from 天安门` | 否（最稳） |
| **地名解析** | 地名/店名 | `--from 杭州西湖` | 要（高德需 key） |
| **本地文件** | 见下面方式 B | `--file my-route.gpx` | 否 |

经纬度写反了会自动纠正（`116.3975,39.9087` 也能认出来）。

**推荐做法：把常用点存成命名地点，只存一次。**

```powershell
# 添加
python tools\mroute.py alias add "家" 39.9087,116.3975
python tools\mroute.py alias add "公司" 39.9928,116.3964 --note "奥体"
python tools\mroute.py alias list          # 查看全部

# 之后直接写名字
python tools\mroute.py gen --preset run --provider osrm --from 家 --to 公司 --out out\commute.json
```

也可以把地名解析的结果直接存下来：

```powershell
$env:AMAP_KEY = "你的key"                  # 高德 key（国内地名/店名最准）
python tools\mroute.py resolve "天安门" --save 天安门
python tools\mroute.py resolve "杭州西湖" --save 西湖
```

命名地点存在项目根目录的 `locations.json`，是纯文本，可以直接编辑、也能提交进版本库共享。

```powershell
python tools\mroute.py alias del "公司"    # 删除
```

> ### ⚠️ 坐标系提示（很容易踩的坑）
>
> 地图选点用的是**高德瓦片**，它是 **GCJ-02（火星坐标）**；而安卓定位、
> OSRM 路网、本工具内部统一用 **WGS-84**。**工具会自动转换**，所以你在图上点的地方、
> 生成出的轨迹、手机上跑的位置三者是一致的。
>
> 但如果你**手动从地图网站复制坐标**填进来，必须说明来源：
>
> | 坐标来源 | 坐标系 | 怎么填 |
> | --- | --- | --- |
> | GPS 设备、OSRM、OSM | WGS-84 | 直接填（默认） |
> | 高德地图 | GCJ-02 | `--coord gcj02` |
> | 百度地图 | BD-09 | `--coord bd09` |
>
> 命名地点也支持：`alias add "公司" <坐标> --coord gcj02`
>
> 不转换的后果：国内整体偏 **500~600 米**（实测北京 555m、上海 479m、
> 深圳 606m）—— 症状就是「电脑上标的路线和手机上地图跑的路线不一致」。

### 怎么确认一个坐标真的在那儿

**「坐标看着像」和「坐标是对的」完全不是一回事。** 这里踩过一次坑：把
`39.9087,116.3975` 当成天安门当基准用了很久，实际那是**皇史宬**，偏 552 米。

用 `audit-aliases.py` 自查：

```powershell
python tools\audit-aliases.py                    # 列出所有命名地点及坐标
python tools\audit-aliases.py 天安门 --reverse    # 联网反查：这坐标是哪儿
python tools\audit-aliases.py 天安门 --render     # 渲染底图 + 红十字，肉眼看落点
```

`--render` 会在 `out/alias-audit/` 生成带十字的高德底图 —— **十字必须落在你
期望的地点图标上**。偏几百米就是坐标或转换有问题。

**推荐流程**：地图选点里点一下 → 记下坐标 → `--render` 看一眼十字落点。
这一步花 10 秒，能省掉后面几小时的迷惑。

### 定位到底有多准（实测误差预算）

```powershell
python tools\error-budget.py
```

链路实测数据（北京，默认 z16）：

| 环节 | 实测误差 | 说明 |
| --- | --- | --- |
| ① 地图选点（像素取整） | **0.92 m** | 已到理论下限（分辨率 1.83 m ÷ 2） |
| ② GCJ-02 ↔ WGS-84 转换 | **0.0000 m** | 往返精确 |
| ③ **OSRM 道路吸附** | **50 ~ 500 m** | ← 唯一的大误差源 |
| ④ 真机上报 vs 轨迹起点 | **0.01 m** | 设备完全一致 |

**第 ③ 环才是「不准」的主因，而且它不是 bug**：路网规划只能沿道路走，
你点在天安门城楼（建筑内部）上，OSRM 只能把起点挪到最近的路，偏 116 米；
点在天坛公园里偏了 510 米。

工具会在生成后**主动报告吸附距离**：

```
⚠ 道路吸附：起点差 112 m，终点差 4 m。
    这是 OSRM 把点吸附到最近道路造成的，不是定位错误 ——
    路网规划只能沿道路走。
```

**怎么把误差压到最小**：

| 做法 | 效果 |
| --- | --- |
| **把点选在道路上**（放大地图能看到路） | 吸附偏移可降到几米 |
| 滚轮放大到 z17/z18 再点 | 选点精度 0.46 m / 0.23 m |
| 用命名地点直接喂精确坐标 | 跳过手点，只剩吸附误差 |
| 放大地图核对：`python tools\verify-route.py <轨迹.json>` | 肉眼看轨迹是否贴路 |

### 拐弯时的「瞬移」与拐角圆滑

如果发现**拐弯时位置突兀一跳**，原因是：**OSRM 给的几何在路口是尖角折线**。
按弧长采样时，某一步会正好跨过这个顶点 —— 位置只挪几十厘米，但**方向瞬间转过去**。

实测（修复前）：一步内 bearing 跳 **180°**，位置转角 >90° 的点有 **322 处**。

工具现在默认做**拐角圆滑**（`--corner-radius 6`）：把尖角替换成圆弧，
转弯分摊到多个采样点上，像真人走弧线。实测效果：

| | bearing>30° 的步数 | 最大 bearing 跳变 |
| --- | --- | --- |
| 关闭圆滑 | 6 | **92.1°** |
| **开启（6m）** | **0** | **22.0°** |

代价是**切掉一点拐角内角**（半径 6m 约切 **1.5m**，与 GPS 噪声同量级）。
调参：

```powershell
--corner-radius 0     # 完全关闭
--corner-radius 6     # 默认，行人过弯
--corner-radius 12    # 车辆路口（切角约 3.6m）
--corner-min-turn 35  # 只圆滑更急的弯
```

### 起终点很近 → 自动问你要不要绕圈

在「多点选路」页点生成时，如果**起点和终点的直线距离 ≤ 250 米**，
会先弹窗问：

```
起点和终点直线距离只有 56 米。

是不是想沿这条路线绕圈？

「是」  = 绕圈（下一步填圈数）
「否」  = 只跑一趟
「取消」= 回去改起终点
```

选「是」后弹出**绕圈设置**窗口，里面会告诉你一圈多远，并让你填圈数：

```
┌─ 按这条路线绕圈 ─────────────────────┐
│ 起终点直线距离 56 米。                │
│ 下面填要跑几圈 —— 每圈沿同一路线跑    │
│ 一次，时间轴连续，不会每圈重新起步。  │
│                                      │
│ 圈数 [8]                             │
│ 一圈路程：约 786 米（0.79 km，按你选的点估算）│
│ 合计约 6.29 km（6288 m）             │
│                        [确定] [取消] │
└──────────────────────────────────────┘
```

「合计」会随你改圈数实时更新。一圈路程优先按你在地图上选的点算；
没有选点时显示「生成后会显示」，生成完在日志里能看到真实里程。

命令行等价写法：

```powershell
python tools\mroute.py gen --preset walk --provider file --file out\ring.txt `
    --laps 5 --out out\ring5.json
```

**时间轴是跨圈接续的** —— 5 圈不是把同一段复制 5 遍各自从 0 开始，
而是连续 5 圈，只在最开始有一次起步加速。实测：圈数翻倍，点数、时长、
里程都同比翻倍（1 圈 / 2 圈 / 4 圈对比误差 <5%）。

> 若想让它**无限循环**（不预设圈数），用 `--mode loop`：那是设备端循环播放
> 同一段轨迹。`--laps N` 则是把 N 圈写进轨迹文件，两种方式按需选。

### 拐弯：按弯的形状决定动作 + 两种手段自动配合

**「离路上限」和「拐弯处理」不是二选一 —— 它们管的是两个不同的误差源。**

| | 改的是 | 能修什么 | 修不了什么 |
| --- | --- | --- | --- |
| **拐角圆滑** | **真路径**（让它像人走弧线） | 方向突变 | 代价是**切角**（真路径偏出中心线） |
| **离路上限** | 只压 **GPS 噪声** | 噪声造成的偏离 | **切角**——真路径已经不在路上，夹不回来 |

实测证据（真实道路）：

| 圆滑半径 | 真路径切角 | 上限设 4m | 上限设 1m |
| --- | --- | --- | --- |
| 0 | 0.00m | 1.90m | 0.48m |
| 6m | **2.00m** | **2.00m** | **2.00m** |

半径 6m 时，**上限从 4 压到 1 完全无效**，卡在 2.00m —— 因为那 2 米是
真路径本身偏出去的。

#### 所以默认是 `auto`：用离路上限的预算去约束圆滑半径

面板上「**圆滑策略**」是一个三选一下拉框（选路页 → 生成参数 → 拐弯约束）：

| 选项 | 含义 | 真路径切角（实测） |
| --- | --- | --- |
| **auto（默认）** | 切角预算 = 离路上限 × 0.25，预算内取最大半径 | 0.75m |
| round | 用你填的半径（选了之后半径框才可编辑） | 6m → 1.76m |
| **none** | **不圆滑：真路径 100% 贴道路中心线** | **0.000m** |

选 `none` 时半径输入框会**自动禁用**（此时半径无意义），旁边提示
「真路径切角 0.000m，100% 贴中心线；拐弯方向是尖角」。

命令行等价写法：

```powershell
--corner-mode auto     # 默认
--corner-mode round --corner-radius 4
--corner-mode none     # 绝对不切角
```

> **`none` 是最好的精度选择，代价是方向。** 它让真路径与道路中心线完全
> 重合（切角严格为 0），但拐弯处方向是**尖角**——采样点跨过顶点时方向会
> 突变。适合「位置精度优先」的场景。
>
> 三种模式的**离路最大距离是一样的**（都受 `--max-offset` 管），差别在
> **真路径**是否被切。实测：none 3.00m / auto 3.00m / round6 3.00m ——
> 因为那 3 米是 GPS 噪声，由离路上限负责。

auto 与 round 的实战对照：

| 策略 | 切角 | 离路中位 | **离路最大** |
| --- | --- | --- | --- |
| **auto（上限 3m）** | 0.67m | 1.11m | **3.00m** ✓ |
| auto（上限 1m） | 0.19m | 0.48m | **1.01m** ✓ |
| round 6m（旧默认） | 1.76m | 1.12m | **3.72m** ✗ 突破上限 |

#### 过弯速度由弯的**形状**决定

用横向加速度模型 `a = v²/r`（转弯靠向心力，它有上限）。半径由形状反推
（弧长 ÷ 转角）。实测（跑步 3.3 m/s，a 上限 3.0）：

| 弯的半径 | 过弯速度 | 占巡航 | 横向加速度 |
| --- | --- | --- | --- |
| 1 m | 0.62 m/s | 19% | 0.38 |
| 2 m | 1.49 m/s | 45% | 1.11 |
| 3 m | 2.40 m/s | 73% | 1.92 |
| 8 m | 3.28 m/s | 99% | 1.34 |
| 30 m | 3.30 m/s | **100%（不减速）** | 0.36 |

**急弯慢、缓弯不减速** —— 这就是「按形状决定动作」。而且刹车是**提前**的
（扫描前方刹停距离，`v_now ≤ √(v_corner² + 2as)`），不是冲进弯才减。

```powershell
--a-lat 1.5     # 走路（默认）；跑步用 3.0；0 = 关闭形状限速
--a-lat 3.0
--a-lat-floor 0.6   # 速度下限，再急的弯也不像爬
```

> `--corner-step-turn` 默认已放宽到 **75°**、`--corner-min-samples` 默认 **1**。
> 这两个是**步长类保护**，与形状限速会互相打架 —— 实测阈值 25° 时半径 1m
> 的弯被压到 0.30 m/s（横向加速度仅 0.09，远低于人的舒适值）；放宽后是
> 0.62 m/s、a=0.38，合理得多。形状限速自然会让急弯落更多采样点（v 小 →
> 步长小 → 点密），不需要额外强制。

### 两组参数各管一件事（别混在一起）

| 参数 | 管什么 | 默认 | 关闭方式 |
| --- | --- | --- | --- |
| `--max-offset` | **离路距离**：上报坐标到道路中心线的上限 | 4 m | `0` |
| `--corner-radius` | **拐角圆滑**：把尖角折线换成圆弧 | 6 m | `0` |
| `--corner-step-turn` | **单步净偏转**：一步之内方向最多转几度 | 25° | `0` |
| `--corner-min-samples` | **弯道内最少采样点**：点太少时方向会突变成一次跳变 | 5 | `1` |

实测互不干扰（真实道路，3.3 m/s 跑步）：

| 离路上限 | 单步转角 | 最少采样点 | 离路最大 | 单步最大转角 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1 | 3.22m | 51.2° |
| **3** | 0 | 1 | **3.00m** | 51.2° ← 只影响距离 |
| 0 | **15** | **5** | 2.95m | **27.0°** ← 只影响方向 |
| **3** | **15** | **5** | **2.35m** | **27.0°** |

### 选模拟类型会自动填好全部参数

控制台的「多点选路」页选定预设（步行 / 跑步 / 间歇 / 自定义）后，
**七项参数会整体覆盖**，不会残留上一个预设的值：

| 预设 | 速度 | 采样 | 噪声σ | 圆滑 | 离路 | 单步转角 | 弯道点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 步行 | 1.35 | 500ms | 1.5 | 6m | 3m | 25° | 5 |
| 跑步 | 3.3 | 1000ms | 2.0 | 8m | 4m | 25° | 5 |
| 间歇训练 | 3.6 | 500ms | 2.0 | 10m | 5m | 25° | 5 |
| 自定义 | 1.4 | 1000ms | 1.5 | 6m | 3m | 25° | 5 |

数值取自 [08-噪声与离路配置表](08-噪声与离路配置表.md)，都满足「上限 ÷ σ ≥ 2」
（实测该比值下「被夹住」的点 <2%，误差分布不会退化）。

生成前还会**校验参数**：非数字、超范围会被拦下；离路上限相对噪声明显偏小时
会弹窗提醒（因为那会让误差分布退化成一个圆，统计上不自然）。

### 拐弯时「突然变向」

如果拐弯处感觉**方向是一瞬间转过去的**（位置没脱离路线，但看着别扭），
原因是速度剖面**进弯前不减** —— 一步正好跨过了整个弯。

实测：3.3 m/s、1s 采样时，单步最大转角达 **84°**；人转弯不会这样。

工具用**两条独立限制**解决（详见上表）：

**① `--corner-step-turn 15`** —— 让**一步之内的净偏转**不超过设定角度。

| 阈值 | 单步最大转角 | 采样点数变化 |
| --- | --- | --- |
| 0（关闭） | 51.2° | 100% |
| 15°（默认） | 27.0° | 105% |

**② `--corner-min-samples 5`** —— 弯道内至少落 5 个采样点。

这条解决的是另一个问题：**采样点太少时，方向只能用一次跳变表达**。
实测 8 m/s、1s 采样时，6m 半径的 90° 弯弧长只有 9.4m 而一步 8m，
弯道内只落 1~2 个点，相位不对时甚至出现 **168° 的伪折返** —— 这不是减速能
解决的，必须保证弯道里有足够采样点。

| 最少采样点 | 3.3 m/s | 5.0 m/s | 8.0 m/s |
| --- | --- | --- | --- |
| 1（关闭） | 28.7° | 25.7° | 27.0° |
| **5（默认）** | **19.3°** | **19.7°** | **21.1°** |
| 10 | 17.7° | 17.7° | 21.0° |

（上面是只看「移动中」的点；排除 v<0.6 的点后大转角全部消失 ——
那些是急弯处速度被压到接近 0 时的方向抖动，真实设备同样如此。）

两条限制都**只在真正需要时触发**：步行时单步本就只有 5~10°，低于阈值，
完全不减速（采样点数 100% 不变）。

```powershell
--corner-step-turn 0     # 关闭净偏转限制
--corner-min-samples 1   # 关闭最少采样点限制
--corner-min-samples 10  # 更严格（弯道更细腻，代价是慢约 12%）
```

> ⚠️ **路径点不要自己摆成"发夹"**（出去再原路折返）。那种情况下 OSRM 会生成
> 一条折返路径，圆滑只能把它变成圆角发夹 —— 看起来仍然像瞬移，因为**路径本身
> 就是这么设计的**。把路径点摆成顺向推进的路线即可。

### 会不会偏出道路？—— 默认不会

虚拟定位**贴着道路走**（路径就是 OSRM 的路网几何），但上报坐标会被 **GPS 噪声**
推离路面。实测：

| 配置 | 中位 | 90分位 | 最大 | 偏出 5m 的点 |
| --- | --- | --- | --- | --- |
| 不限制（旧行为） | 1.48m | 4.20m | **7.71m** | **431** |
| **默认（离路上限 4m）** | 1.18m | 2.60m | **4.49m** | **0** |

**默认 `--max-offset 4`**：上报坐标到**道路中心线**的距离超过 4 米就沿噪声方向
拉回来。三个预设实测：

| 预设 | 中位 | 最大 | 偏出 5m 的点 |
| --- | --- | --- | --- |
| walk | 1.18m | 4.49m | 0 |
| run | 1.21m | 4.64m | 0 |
| interval | 0.86m | 4.33m | 0 |

注意拉回的是**离中心线的垂直距离**，不是把噪声去掉 —— 抖动仍然保留（看起来还是
真实 GPS），只是不会偏进建筑或绿化带。

调参：

```powershell
--max-offset 0     # 关闭限制（保留纯噪声行为，会偏出路面）
--max-offset 4     # 默认，城市道路 + 人行道的路廊宽度
--max-offset 2     # 更严格（小路、巷道）
--max-offset 8     # 宽松（含停车场/广场的园区道路）
```

**离路上限 vs 噪声：这两个要搭配调。** 「被夹住的点」占比只取决于
`上限 ÷ 噪声σ` 这个比值 —— 想保持在 1% 以下，**上限至少要是 σ 的 3~4 倍**：

| 配置 | 中位 | 90分位 | 被夹占比 | 评价 |
| --- | --- | --- | --- | --- |
| σ=2.0，上限 4（默认） | 1.63m | 3.20m | **0.9%** | 分布连续 ✓ |
| σ=2.0，上限 1 | 0.74m | 0.99m | **12.4%** | 一堆点贴同一半径 ✗ |
| σ=1.0，上限 2 | 0.81m | 1.60m | **0.9%** | 分布连续 ✓ |
| σ=0.5，上限 1 | 0.41m | 0.80m | **0.9%** | 分布连续 ✓ |

「被夹住」指坐标正好落在上限上 —— 真实 GPS 的误差是连续的，不会有一堆点
落在同一半径，所以夹太多反而是可被检测的痕迹。

**想贴路到 1 米级**，正确做法是**同时降噪声**，而不是只压上限：

```powershell
# 高精度步行：90分位 <1m，分布仍自然
python tools\mroute.py gen --preset walk --noise 0.5 --max-offset 1 `
    --from 天安门城楼 --to 天坛公园 --out out\precise.json
```

**物理下限约 0.9 米** —— 那是均匀采样的离散误差（一步跨过弯道时，直线插值
偏离真实路径），与 GPS 无关。想更低只能加密采样：`--interval 250`。

> 起步阶段（lead-in）的漂移半径也会按上限收敛。否则「不许离路超过 1 米」
> 和「起步时撒到 4 米外」两个设定会自相矛盾。

> 「命名地点」存的是**加过坐标转换的 WGS-84**，可以直接手填，也可以从
> 高德复制后加 `--coord gcj02`，避免手点的像素误差。


**在图形控制台里更简单**：

- 「生成轨迹」页有**命名地点下拉框**，选中点「设为起点/终点」即可
- **地图选起点 / 地图选终点** —— 用鼠标在真实地图上点（单击定位、双击确认、拖动平移、滚轮缩放）
- **地图里还能直接检索** —— 输入「天安门」回车，列表里挑一个，地图跳过去
- **读设备位置** —— 直接把手机当前位置填进起点
- **把起点存为命名地点** —— 随时把当前坐标存起来
- 「**多点选路**」页可以一次点出起点 + 多个途经点 + 终点，连成自定义路线

### 地名检索（不确定坐标时用）

```powershell
# 列候选
python tools\mroute.py search "天安门" --limit 5
python tools\mroute.py search "西湖 杭州"                        # 加城市限定更准
python tools\mroute.py search "公园" --near 39.9087,116.3975      # 偏向该坐标附近

# 直接取第 N 个；--save 顺手存成命名地点
python tools\mroute.py search "天坛" --pick 3 --save 天坛公园
```

检索来源依次尝试：**高德**（配了 `AMAP_KEY` 就用，国内 POI 最全）→ **Photon**
（免费、无需 key，实测国内可达）→ Nominatim（国内常超时）。

> ⚠️ 实测 `search "天坛"` 第一条是**广西南宁**的同名村，第三条才是北京的
> **天坛公园**。所以要么加城市限定（`天坛 北京`），要么用 `--pick` 挑。
> OSM 系服务对中文 POI 的覆盖不如高德，小店铺/小区名往往查不到 —— 这时用命名地点。

> 「读设备位置」在部分机型上读不到：Android 10+ 会对 `dumpsys location` 的输出做
> **隐私打码**（坐标显示成 `39.9******`）。实测本机的荣耀 9X 就是这样。
> 这时改用「地图选点」或命名地点。

### 方式 A：真实路网（需要网络）

```powershell
python tools/mroute.py gen `
    --from 39.9075,116.3910 `
    --to   39.9200,116.4100 `
    --provider osrm --profile driving --speed 13.9 `
    --out out/drive.json
```

- `--provider osrm` 用的是 OSRM 官方演示服务器，**免费、无需 key**，适合测试（有频率限制，别拿来批量跑）。
- `--speed 13.9` 是 50 km/h，开车；步行用 `1.4`，跑步 `3`，骑行 `5`。
- `--profile` 影响 OSRM 走哪套路网（`driving` / `foot` / `bike`；演示服务器实际只提供 driving 轮廓）。

输出会打印摘要：

```

路网里程: 3821 m   预计耗时: 275 s
```

### 方式 B：本地路径文件（不联网）

```powershell
python tools/mroute.py gen --provider file --file examples/road-to-tiantan.txt `
    --speed 1.4 --out out/demo.json
```

`--file` 支持三种格式，自动识别：

| 格式 | 样子 |
| --- | --- |
| 纯文本 | 每行 `纬度,经度`（写成 `经度,纬度` 也能自动判断），`#` 注释 |
| GeoJSON | `LineString` / `MultiLineString` / `Feature` / `FeatureCollection` |
| GPX | `<trkpt lat="" lon="">` 轨迹点 |

### 方式 C：用国内路网（需要高德 key）

```powershell
$env:AMAP_KEY = "你的key"
python tools/mroute.py gen --from 39.9075,116.3910 --to 39.9200,116.4100 `
    --provider amap --amap-mode driving --speed 13.9 --out out/amap.json
```

高德返回的是 **GCJ-02**，脚本会自动反解成 WGS-84（因为 Android 给应用的是 WGS-84）。
这个转换在 `tools/mockroute/geo.py` 里，精度约 1cm。**不做这一步会有几十到几百米的系统性偏移。**

### 常用调参

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `--speed` | 目标速度 m/s | 步行 1.4 / 跑步 3 / 骑行 5 / 城市开车 8~14 |
| `--interval` | 采样间隔 ms | 默认 1000；要更细的轨迹用 500 |
| `--accel` | 加速度上限 m/s² | 默认 0.4（像人）；开车可以 1.0~2.0 |
| `--jitter` | 坐标抖动米数 | 默认 0；想更「脏」可以给 2~5 |
| `--mode` | `once` / `loop` / `pingpong` | 长跑用 loop |
| `--lead-in` | 起步前原地漂移点数 | 默认 3，模拟 GPS 刚锁星 |
| `--seed` | 随机种子 | 固定后可复现同一份轨迹 |
| `--start-offset` | 从路径起点跳过多少米 | 想从中途开始走 |

## 第三步：让手机走起来

```powershell
python tools/mroute.py play --route out/drive.json
```

它做三件事：

1. 把轨迹推到 `/sdcard/Android/data/com.mockroute/files/route.json`
2. 发一条 `START_ROUTE` 广播
3. 本地倒计时，方便你知道什么时候走完（`--no-wait` 可以不等）

手机端会按时间戳自己插值写点，PC 不再参与，所以时间长也不掉精度。

### 运行中调整

```powershell
python tools/mroute.py mult 2.5      # 2.5 倍速（轨迹内容不变，只是走得快）
python tools/mroute.py pause         # 暂停
python tools/mroute.py resume        # 恢复
python tools/mroute.py status        # 查状态（从手机 logcat 捞）
python tools/mroute.py stop          # 停止并移除 mock provider
```

### 循环跑

```powershell
python tools/mroute.py play --route out/loop.json --mode loop
```

配合 [examples/route-loop.geojson](../examples/route-loop.geojson) 可以做一个 300m 见方的闭环，无限绕圈。

## 其它玩法

### 原地转圈（防止被判定为「静止」）

```powershell
# 绕天安门半径 100m 转圈，一圈 60 秒（等效 10.5 m/s ≈ 38 km/h）
python tools/mroute.py circle --at 39.9075,116.3910 --radius 100 --period 60
```

### 平滑地「走」到某个点

```powershell
python tools/mroute.py goto --at 39.9200,116.4100 --speed 1.4
```

它会读当前虚拟位置，算直线距离，按速度匀减速抵达——比直接跳过去自然得多。

### 在 PC 上做交互式调试（直推模式）

```powershell
python tools/mroute.py play --route out/demo.json --direct --speed-scale 4
```

PC 逐点广播，方便随时 Ctrl+C 或改参数。代价是频率上限约 2~5 Hz，
超过 1000 个点会很慢，长轨迹**不要**用这个模式。

### 只想看命令不想执行

```powershell
python tools/mroute.py play --route out/demo.json --dry-run
```

输出所有会执行的 adb 命令，方便你复制、改写或放进自己的脚本。
**这个模式不需要装 adb，也不需要连手机。**

## 进阶：接到自己的系统里

如果你要把虚拟定位接进自动化测试框架，有两条路：

1. **直接调 CLI**：`subprocess.run(["python", "tools/mroute.py", "play", ...])`，
   用退出码判断成败（`0` 成功 / `1` 运行错误 / `2` 参数错误）。
2. **当库用**：

```python
import sys
sys.path.insert(0, "tools")
from mockroute.protocol import Adb, find_adb
from mockroute.player import Player, quick_route

route, res = quick_route(
    (39.9075, 116.3910), (39.9200, 116.4100),
    provider="osrm", speed=13.9, interval_ms=500, seed=42,
)
player = Player(Adb(exe=find_adb()), verbose=True)
player.prepare()
player.play_route(route, __import__("pathlib").Path("out/x.json"))
```

广播协议本身很简单，见 [03-广播协议](03-广播协议.md)——你完全可以用 Kotlin/Java/Go 写自己的客户端。
