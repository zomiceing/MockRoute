# 03 · 广播协议参考

PC 与手机之间只有一种通信方式：`am broadcast`。
契约的唯一来源是两个文件，改一边必须同时改另一边：

| 侧 | 文件 |
| --- | --- |
| PC | `tools/mockroute/protocol.py` |
| Android | `mockroute-android/app/src/main/java/com/mockroute/Protocol.kt` |

`tests/test_mockroute.py::test_constants_match_android_source` 会校验两边的字面量一致，
所以改漏了会被测试拦住。

---

## 基本形式

```
adb shell am broadcast \
    -a <action> \
    -n com.mockroute/.ControlReceiver \
    --receiver-foreground \
    [extra...]
```

- `-n` 必须带：显式指定组件，绕开 Android 8+ 的隐式广播限制。
- `--receiver-foreground`：让接收器以临时前台身份运行，规避后台广播限制。
- 接收器 `exported=true`，因为投递方是 shell（uid 2000）。

**可选参数**：`--user <id>`（多用户设备）、`-s <serial>`（多设备时 adb 的参数，不是 am 的）。

---

## action 全表

| action | 作用 | 必需 extra | 可选 extra |
| --- | --- | --- | --- |
| `com.mockroute.action.SET` | 设置单个固定位置（会持续重发） | `lat` `lon` | `speed` `bearing` `acc` `alt` |
| `com.mockroute.action.START_ROUTE` | 回放轨迹文件 | `file` | `mode` |
| `com.mockroute.action.START_CIRCLE` | 绕中心点画圈 | `lat` `lon` | `radius` `period` |
| `com.mockroute.action.GOTO` | 从当前位置直线前往 | `lat` `lon` | `speed` |
| `com.mockroute.action.SPEED` | 调整回放倍速 | `mult` | — |
| `com.mockroute.action.PAUSE` | 暂停回放 | — | — |
| `com.mockroute.action.RESUME` | 恢复回放 | — | — |
| `com.mockroute.action.STOP` | 停止并移除 mock provider | — | — |
| `com.mockroute.action.STATUS` | 打印当前状态到 logcat | — | — |
| `com.mockroute.action.START` | 预留（等价于 START_ROUTE） | — | — |

## extra 类型对照

`am broadcast` 的 extra 必须带类型前缀，传错类型会静默读成默认值（这是最常见的坑）：

| extra | 类型 | am 前缀 | 含义 | 默认值 |
| --- | --- | --- | --- | --- |
| `lat` | double | `--ef` | 纬度（WGS-84） | 无（必需） |
| `lon` | double | `--ef` | 经度 | 无（必需） |
| `file` | string | `--es` | 轨迹文件路径（可为文件名，会解析到应用私有目录） | `route.json` |
| `mode` | string | `--es` | `once` / `loop` / `pingpong` | 文件里的值 |
| `speed` | float | `--ef` | 上报速度 m/s | `0` |
| `bearing` | float | `--ef` | 上报方位角（0=正北，顺时针） | `0` |
| `acc` | float | `--ef` | 上报精度（米） | `8` |
| `alt` | float | `--ef` | 上报海拔（米） | `0` |
| `radius` | float | `--ef` | 圆圈半径（米） | `100` |
| `period` | long | `--el` | 转一圈的毫秒数 | `60000` |
| `mult` | float | `--ef` | 回放倍速，范围 0.05~50 | `1` |
| `interval` | int | `--ei` | 仅解析轨迹时用于补 `t` | `1000` |
| `tag` | string | `--es` | 预留标签 | 空 |

> ⚠️ **`am broadcast` 没有 `--ed`（double）选项**，浮点值只能用 `--ef`（float）。 Android 的 TypedValue 把 FLOAT(4) 和 DOUBLE(5) 当作不同类型：设备端 `getDoubleExtra()` 读一个 float extra 只会拿到默认值，于是报「缺少 lat/lon」，而 `am broadcast` 依然返回成功 —— 极难排查。Android 端用容错读取（float/double/String 都能读），因此无论调用方怎么发都不会踩坑。
> 写错了不会报错，只会读到默认值——`mroute` 的 `--dry-run` 输出可以直接抄。

## 手写示例

### 固定一个位置

```powershell
adb shell am broadcast -a com.mockroute.action.SET `
  -n com.mockroute/.ControlReceiver --receiver-foreground `
  --ef lat 39.9075 --ef lon 116.3910 --ef speed 1.4 --ef bearing 90 --ef acc 8
```

### 回放轨迹（循环）

```powershell
adb push out\demo.json /sdcard/Android/data/com.mockroute/files/route.json
adb shell am broadcast -a com.mockroute.action.START_ROUTE `
  -n com.mockroute/.ControlReceiver --receiver-foreground `
  --es file route.json --es mode loop
```

### 转圈 + 提速 + 停止

```powershell
adb shell am broadcast -a com.mockroute.action.START_CIRCLE `
  -n com.mockroute/.ControlReceiver --receiver-foreground `
  --ef lat 39.9075 --ef lon 116.3910 --ef radius 150 --el period 45000

adb shell am broadcast -a com.mockroute.action.SPEED `
  -n com.mockroute/.ControlReceiver --receiver-foreground --ef mult 3

adb shell am broadcast -a com.mockroute.action.STOP `
  -n com.mockroute/.ControlReceiver --receiver-foreground
```

### 看状态

```powershell
adb logcat -c
adb shell am broadcast -a com.mockroute.action.STATUS `
  -n com.mockroute/.ControlReceiver --receiver-foreground
adb logcat -d -s MockRoute:I
```

## 轨迹文件格式

默认位置：`/sdcard/Android/data/com.mockroute/files/route.json`
（`--es file` 给文件名会解析到这个目录，给绝对路径则按绝对路径读）

```json
{
  "version": 1,
  "mode": "once",
  "interval": 1000,
  "source": "osrm(...) 路网3821m/275s",
  "points": [
    {"t": 0,    "lon": 116.3910, "lat": 39.9075, "speed": 0.0,  "bearing": 90.0, "acc": 9.4, "alt": 0.0},
    {"t": 1000, "lon": 116.3913, "lat": 39.9075, "speed": 0.31, "bearing": 90.0, "acc": 6.1, "alt": 0.0}
  ]
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `t` | 是 | 相对轨迹起点的毫秒数，**必须单调不减**；缺失则按 `interval` 顺推 |
| `lat` `lon` | 是 | WGS-84，7 位小数 |
| `speed` | 否 | m/s；缺失或为 0 时设备端按相邻点几何补算 |
| `bearing` | 否 | 度；同上 |
| `acc` | 否 | 精度（米），默认 8 |
| `alt` | 否 | 海拔（米），默认 0 |

顶层 `mode` 支持 `once` / `loop` / `pingpong`，广播里的 `mode` 会覆盖它。

**也支持 CSV**（文件名以 `.csv` 结尾时）：

```csv
t,lon,lat,speed,bearing,acc,alt
0,116.3910,39.9075,0.0,90.0,9.4,0.0
1000,116.3913,39.9075,0.31,90.0,6.1,0.0
```

首行可以是表头，也支持 `#` 注释行。分隔符支持逗号/分号/制表符。

## 设备端行为细节

服务会同时向这些 provider 写点（存在且能注册的都会写）：

- `gps`（必定尝试）
- `network`（必定尝试）
- `fused`（Android 12 / API 31+ 才存在）

**为什么三个都写**：只写 `gps` 时，目标 App 若用 `FusedLocationProviderClient` 或
`NETWORK_PROVIDER` 取位置，会读到真实定位，表现为「有的 App 有效、有的无效」。

每个点的写入要点：

- `time` 取当前墙钟；`elapsedRealtimeNanos` 单调递增（否则部分 App 会丢弃更新）；
- Android 8+ 额外填 `verticalAccuracyMeters` / `speedAccuracy` / `bearingAccuracy`；
- **不使用反射**去改 `Location.isFromMockProvider` 之类的隐藏字段 —— Android 9+ 对隐藏
  API 的反射限制会让 App 直接崩溃，而 `isFromMockProvider()` 本身仍是公开可读的 `true`。

## 退出码约定（CLI）

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 运行中出错（设备未连接、adb 失败、网络错误…） |
| `2` | 参数/输入错误（坐标格式、文件不存在、轨迹校验失败） |

`130` 表示被 Ctrl+C 中断。
