# 04 · 排障

先跑一次体检，它会把绝大多数原因直接指出来：

```powershell
python tools/mroute.py doctor --fix
```

下面是逐项的症状对照。

---

## A. 连不上手机

### `adb devices` 是空的

| 检查 | 处置 |
| --- | --- |
| 线材 | 换成确定能传数据的线，纯充电线只能供电 |
| USB 口 | 换主板后置口，别用前面板或 USB hub |
| 驱动 | Windows 设备管理器里看有没有黄色感叹号，装厂商驱动或 Google USB Driver |
| USB 模式 | 手机上把 USB 配置改成「传输文件 (MTP)」 |
| 调试开关 | 开发者选项 → USB 调试；华为/荣耀还要开「仅充电模式下允许 ADB 调试」 |

### 显示 `unauthorized`

手机上的「允许 USB 调试」弹窗没点允许。

```powershell
adb kill-server
# 手机上：开发者选项 → 撤销 USB 调试授权
adb start-server
adb devices
```

重新插线，这次勾上「一律允许」。

### 显示 `offline`

```powershell
adb kill-server
adb start-server
adb devices
```

还不行就重启手机。

### 多台设备时报 `more than one device`

```powershell
adb devices
python tools/mroute.py doctor --serial ABCD1234
# 或者设环境变量：$env:ANDROID_SERIAL = "ABCD1234"
```

## B. 命令成功但定位不动（最常见）

### B1. 模拟位置没授权

`am broadcast` 会返回 `Broadcast completed: result=0` —— 但这**不代表写点成功**。
权限不对时服务会注册 provider 失败，日志里能看到。

```powershell
python tools/mroute.py logs
```

如果看到：

```
mock provider 就绪: []  失败: [gps(SecurityException), network(SecurityException)]
无法注册任何 mock provider。请在开发者选项中把 MockRoute 设为「模拟位置信息应用」…
```

就是这个问题：

```powershell
adb shell appops set com.mockroute android:mock_location allow
adb shell appops get com.mockroute android:mock_location   # 必须含 allow
```

或用 `doctor --fix`。

**小米用户注意**：需要额外打开「USB 调试（安全设置）」，否则 appops 可能被拒绝。
另外 MIUI 的「开发者选项 → 模拟位置信息应用」有时不生效，必须用 appops。

### B2. 只有部分 App 有效

MockRoute 会同时写 `gps`/`network`/`fused`。如果某个 App 仍读到真实位置，可能：

- 该 App 用 `FusedLocationProviderClient` 且系统版本 < Android 12（没有 `fused` 这个 mock provider）。
  → 试试在开发者选项里把「Google 定位精确度」关掉；
- 该 App 自己做了传感器融合（加速度计/陀螺仪与轨迹不符）；
- 该 App 读的是缓存位置。多等几秒，或先停掉再重启该 App。

### B3. 目标 App 在读定位但显示原位置

检查目标 App 是否被授予了定位权限，以及是否在「后台定位」白名单里（有些 App 在前台才更新）。

另外确认你改的是**同一台设备**：

```powershell
adb devices          # 确认只有一台，或已用 --serial 指定
```

---

## C. 走了几步就停 / 跑到一半不动

### C1. 后台被系统冻结

```powershell
adb shell am get-standby-bucket com.mockroute
```

如果结果是 `rare` / `restricted` / `never`，说明应用被系统降级：

```powershell
adb shell am set-standby-bucket com.mockroute active
```

再到手机设置里把 MockRoute 的电池优化设为「无限制」。
小米还要在「后台弹出界面」和「自启动」里放行。

`play --standby-fix` 会自动做前面那一步。

### C2. 服务被杀

```powershell
python tools/mroute.py logs
```

看到「服务已停止，mock 已移除」说明服务被杀了。
`MockLocationService` 用 `START_STICKY`，重启后不会自动恢复播放（这是有意为之，
避免轨迹莫名从头再来）。重新 `play` 一次即可。

### C3. 屏幕锁定导致限制

部分 ROM 在锁屏后会限制后台定位。调试期间把「不锁定屏幕」打开。

---

## D. 轨迹跑得不对

### D1. 速度看起来不对

`play --mult 2` 只改**回放节奏**，不改轨迹里的 `speed` 字段。
如果你要「坐标速度值也是 2 倍」，得重新 `gen --speed <两倍>`。

### D2. 位置整体偏移几十到几百米

坐标系不一致。典型来源：

- 起终点坐标是从高德/腾讯/百度复制的 → 那是 GCJ-02 / BD-09，要加 `--coord gcj02` 或 `--coord bd09`；
- 路径文件来自国内数据源，但没声明坐标系 → 同上；
- 用了 `--provider amap` 但自己又手工转了一次坐标（脚本已经转过了，会双重偏移）。

`gen` 的摘要里如果「直线距离」和「沿路径里程」差得离谱，通常就是坐标有问题。

### D3. 点之间跳得厉害

- `--interval` 太大（比如 5000ms）→ 改成 1000 或 500；
- 路径文件本身点太稀（比如两点相隔 2km）→ 脚本会 densify 到 25m，但原始形状本身是折线就会走折线；
- 用了 `--jitter` 且值过大 → 减小或去掉。

### D4. `轨迹校验失败: 第 N 个点的 t …`

`t` 必须单调不减。手工编辑过 JSON 的话检查一下顺序，或者干脆重新 `gen`。

### D5. 轨迹文件推不进去

```powershell
adb shell ls -la /sdcard/Android/data/com.mockroute/files/
```

目录不存在 → App 从没启动过。启动一次：

```powershell
adb shell am start -n com.mockroute/.MainActivity
```

`doctor` 的第 7 项就是在检查这个。

## E. 命令本身的问题

### E1. `找不到 adb`

```powershell
python tools/mroute.py doctor --adb "D:\Android\Sdk\platform-tools\adb.exe"
# 或把 platform-tools 加进 PATH
```

### E2. `设备上没装 com.mockroute`

```powershell
adb install -r mockroute-android\app\build\outputs\apk\debug\app-debug.apk
```

APK 还没编译 → 见 [01-环境准备](01-环境准备.md) 第 3 节。

### E3. `INSTALL_FAILED_UPDATE_INCOMPATIBLE`

签名变了。

```powershell
adb uninstall com.mockroute
adb install app-debug.apk
```

### E4. 编译失败

| 报错 | 原因 |
| --- | --- |
| `Unsupported class file major version` | JDK 版本不对，需要 **17** |
| `Failed to install the following SDK components` | 没接受许可 → `pwsh -File scripts/setup-android.ps1` |
| `Could not find com.android.tools.build:gradle` | 网络问题，配 gradle 代理或换仓库镜像 |
| `SDK location not found` | 缺 `mockroute-android/local.properties` → 重新跑 setup 脚本 |

### E5. PowerShell 脚本报「禁止运行脚本」

Windows 默认的执行策略不允许运行 `.ps1`：

```
无法加载文件 ...\setup-android.ps1，因为在此系统上禁止运行脚本。
```

**只对这一条命令放行**（不改系统策略，最安全）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-android.ps1
```

永久放开当前用户（有安全代价，二选一）：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

> 另外：这些脚本刻意写成**纯 ASCII**。因为 Windows PowerShell 5.1 在没有 UTF-8 BOM
> 时按 ANSI 读 `.ps1`，中文注释会变成乱码，甚至因为字节序列被误判而直接报语法错误。
> 如果你用编辑器重存过脚本，请存成「UTF-8 with BOM」，或者干脆保持纯 ASCII。

### E5b. TLS 握手失败（`SEC_E_NO_CREDENTIALS`）

症状：任何 HTTPS 下载都失败。

```
curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)
Invoke-WebRequest: 基础连接已经关闭: 接收时发生错误。
```

**这不是网络问题。** 自检可以确认：

```powershell
# DNS 正常
Resolve-DnsName dl.google.com
# TCP 443 也通
Test-NetConnection dl.google.com -Port 443     # TcpTestSucceeded=True
# 但 HTTPS 就是失败
curl.exe -sS -o NUL -w "%{http_code}" https://dl.google.com/
```

DNS 和 TCP 都通、只有 TLS 握手失败 → 是 Windows 证书/凭据子系统（schannel）的问题，
它同时影响 `Invoke-WebRequest`、`curl.exe`、`bitsadmin` 等所有走 schannel 的客户端。

**绕过办法**：改用不依赖 schannel 的客户端。Python 自带 OpenSSL，所以：

```powershell
python tools/fetch.py https://example.com/file.zip out\file.zip
```

`tools/fetch.py` 支持断点续传（下载中断后重跑会接着下），
`scripts/setup-android.ps1` 内部就是用它下载的，所以这个故障不会阻塞安装流程。

修复 schannel 本身通常需要重装/修复系统证书存储，属于系统级维护，不建议为了这个工具去动。

### E6. `--dry-run` 也要 adb？

不用。`--dry-run` 走的是占位可执行名，不查找也不调用真实 adb，没装 SDK 的机器也能用来预览命令。

## F. 还是不行

收集这些信息，能定位到 90% 的问题：

```powershell
# 1) 环境
python tools/mroute.py doctor

# 2) 手机端日志（另开一个窗口）
python tools/mroute.py logs

# 3) 实际下发的命令
python tools/mroute.py play --route out\demo.json --dry-run

# 4) 手动发一条，看系统怎么回
adb shell am broadcast -a com.mockroute.action.STATUS `
  -n com.mockroute/.ControlReceiver --receiver-foreground
adb logcat -d -s MockRoute:I
```

`am broadcast` 的输出里如果有 `Permission Denial`，说明广播被系统拦了
（这条命令必须通过 adb shell 发；从普通应用发需要加权限）。

## G. adb / 构建相关的环境坑（实测踩过，已修）

这一节记录的是**真实的、非显然的**故障模式，都已在本仓库的脚本里处理掉。
如果你换台机器重来，大概率还会遇到其中几个。

### G1. `adb devices` 为空且 adb 自己崩掉

症状：

```
F adb.ex : adb_utils.cpp:315 Cannot mkdir 'C:\Users\<user>\.android': Permission denied
F adb     : main.cpp:54 cannot open C:\Users\<user>\AppData\Local\Temp\adb.log: Permission denied
* failed to start daemon
```

原因：**adb daemon 是脱离当前会话的长命进程，不继承沙箱的文件写入授权**。
它需要三个可写位置，默认都在工作区外，于是直接崩。

处置：把这三处都指到工作区内（`scripts/mroute.ps1` 已经做好，无需手动）：

```powershell
$env:ANDROID_USER_HOME = "$PWD\.toolchain\android-home"
$env:ADB_VENDOR_KEYS   = $env:ANDROID_USER_HOME
$env:TMP = "$PWD\.toolchain\tmp"
$env:TEMP = $env:TMP
```

### G2. 手机一直 `unauthorized`，且从不弹授权框

根因常常在电脑侧。看 adb 的详细日志：

```powershell
adb nodaemon server -vvv      # 另开一个窗口，然后再运行 adb devices
```

如果看到：

```
E adb.e : auth.cpp:84  Failed to open C:\Users\<user>\.android\adbkey: Permission denied
E adb.e : auth.cpp:220 Failed to generate new key
W adb.e : auth.cpp:441 Failed to get user public key
```

说明 **adb 连密钥都没有** —— 它压根没向手机发起授权请求，手机当然不弹窗。
注意 `$ADB_VENDOR_KEYS` 只是「额外」密钥来源；adb 仍会去 `~/.android/adbkey`
读用户主密钥，读不到就放弃。

处置：显式生成密钥，并让硬编码路径也能读到（私钥仍留在工作区）：

```powershell
$ah = "$PWD\.toolchain\android-home"
adb kill-server
adb keygen "$ah\adbkey"
cmd /c rmdir "$env:USERPROFILE\.android" 2>nul
cmd /c mklink /J "$env:USERPROFILE\.android" "$ah"
adb start-server
```

然后在手机上按**这个顺序**操作：

1. 开发者选项 → **撤销 USB 调试授权**
2. USB 调试开关关掉、等几秒、再打开
3. 找一下「**仅充电模式下允许 ADB 调试**」，有就打开（荣耀/华为特有）
4. 拔线 → **重启手机**（很多 EMUI 版本必须重启才会重新弹窗）
5. 插线、解锁亮屏，点「允许」并勾「一律允许」

> 手机弹窗上的 RSA 指纹就是 `adbkey.pub` 的 SHA256。
> 实测有效：本机 Honor 9X（HLK-AL00 / EMUI 13 / Android 10）就是靠这套流程才授权成功。

### G3. Gradle 报 `Failed to create parent directory ...\.gradle`

这是**项目路径含非 ASCII 字符**导致的（比如路径里有 `—` em dash、中文目录名）。
Gradle daemon 日志里路径会先变成乱码，形如：

```
[DEBUG] jars (D:\some\path\.toolchain\gradle-home\caches\jars-9) ...
```

紧接着 AGP 还会独立地再拒绝一次：

```
> Your project path contains non-ASCII characters.
```

**目录联接（junction）解决不了**：JVM 会把链接解析回真实（非 ASCII）路径，失败照旧。

处置：见 [01-环境准备](01-环境准备.md) 第 3.1 节 —— 用 `scripts/prep-build.ps1`
把工程镜像到工作区内的纯 ASCII 目录（`build-ws/`）再构建。`build-android.ps1`
会自动调用，你不用管。

### G4. `sdkmanager` 卡在 `Computing updates...`

`sdkmanager` 走 Java 的 TLS 栈，在某些机器上访问 dl.google.com 会**永久挂住**
（与 G5 的 schannel 问题同源）。但官方 zip 直链是可用的。

处置：用 `tools/sdk-direct.py` 直接下载落位：

```powershell
python tools/sdk-direct.py --sdk .toolchain\android-sdk
```

它处理了几个坑：`build-tools_r34-windows.zip` 内部顶层目录叫 `android-14`
（必须改名成 `34.0.0`）；`platforms;android-34` 在仓库里叫 `platform-34-extNN_rNN.zip`；
以及写入 `licenses/` 的许可哈希（否则 Gradle 报「未接受许可」）。

### G5. 所有 HTTPS 下载都失败：`SEC_E_NO_CREDENTIALS`

见上面 **E5b** 一节。一句话：DNS/TCP 都通、只有 TLS 握手失败 → 改用 Python 下载。

### G6. `am broadcast` 返回成功，但设备端说「缺少 lat/lon」

**这个坑最隐蔽。** Android 的 TypedValue 把 FLOAT(4) 和 DOUBLE(5) 当作不同类型：
设备端用 `Bundle.getDoubleExtra()` 去读一个 float extra 时**直接返回默认值**，
不抛异常。而 `am broadcast` 依然打印成功。

还要注意：**`am broadcast` 并没有 `--ed`（double）选项**，可用的只有
`--ef`（float）/ `--ei`（int）/ `--el`（long）/`--es`（string）。所以不能靠改发
`--ed` 绕过（实测会报 `Unknown option: --ed`）。

正确做法是**两端配合**：

- PC 侧一律发 `--ef`；
- 设备端用能同时接受 float / double / String 的容错读取
  （`MockLocationService` 里的 `dbl()` / `flt()`）。

自己写客户端时照这个模式来就不会踩。
