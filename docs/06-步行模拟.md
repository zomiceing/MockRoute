# 步行模拟使用说明

这份文档只讲**步行模拟**这一件事，从头到尾可以照着做。
其他场景（开车、转圈、单点）见 [02-快速开始](02-快速开始.md)，协议细节见 [03-广播协议](03-广播协议.md)。

## 一、30 秒跑起来

确认环境就绪（[01-环境准备](01-环境准备.md)），手机已授权、APK 已装好，然后：

```powershell
# 1) 生成一条步行轨迹（走真实人行道路网）
python tools\mroute.py gen --preset walk `
    --from 39.90870,116.39750 `
    --to   39.88220,116.40660 `
    --provider osrm --profile foot `
    --out out\walk.json

# 2) 看一眼轨迹长什么样（强烈建议，能提前发现路径/噪声问题）
python tools\plot-route.py out\walk.json -o out\walk.png

# 3) 推到手机开始走
powershell -ExecutionPolicy Bypass -File scripts\mroute.ps1 play --route out\walk.json
```

`--preset walk` 是全部关键点：它一次性把**采样间隔、加速度、GPS 噪声、上报精度**都设成适合步行的值。不用自己逐个试参数。

> **不想联网？** 换成 `--provider file --file examples\road-to-tiantan.txt`（去掉 `--from/--to`）。

## 二、`--preset walk` 到底设了什么

| 参数 | 默认值 | walk 预设 | 为什么这么改 |
| --- | --- | --- | --- |
| `--speed` | 1.4 m/s | **1.35 m/s** | 成年人正常步速 1.2~1.4 m/s |
| `--interval` | 1000 ms | **500 ms** | 采样更密 → 轨迹更平滑；步行一步只走 0.68m，1 秒一个点会显得很"跳" |
| `--accel` | 0.4 m/s² | **0.22 m/s²** | 人起步/停步比车平缓得多；0.22 是实测步行的量级 |
| `--noise` | 0（关） | **2.0 m** | GPS 定位误差标准差。手机在城市里通常 3~8m，天空开阔处 1.5~3m |
| `--noise-alpha` | 0.99 | 0.99 | 误差的时间相关性（见下节，这是最关键的一个参数） |
| `--acc-mean` | 8 m | **6 m** | 上报的 accuracy 均值，贴近真实手机 |

**显式传的参数不会被预设覆盖**。例如想让步速快一点：

```powershell
python tools\mroute.py gen --preset walk --speed 1.6 --from ... --to ... --out out\fast.json
```

## 三、理解 GPS 噪声（这是"像不像真的"的核心）

### 3.1 为什么不能用白噪声

真实 GPS 的定位误差**不是**每个点独立乱跳的。接收机在一个时段内有一个几米级的固定偏差，
这个偏差会缓慢漂移。表现为：连续几个点的误差几乎一样，整体轨迹在真实路径附近缓慢游走。

所以本工具用 **AR(1) 一阶低通**生成误差：

```
n[k] = alpha · n[k-1] + w[k]
```

`alpha` 越大，误差越"粘"（漂移越慢），相邻点的误差越接近。这个参数比噪声大小更重要：

| alpha | 相关长度（500ms 采样） | 效果 |
| --- | --- | --- |
| 0.85 | 约 3 秒 | 误差变化太快，轨迹呈锯齿状，**比不加噪声更假** |
| 0.95 | 约 10 秒 | 偏快 |
| **0.99** | **约 50 秒** | 默认值。接近真实民用 GPS 的表现 |
| 0.995 | 约 100 秒 | 误差几乎变成固定偏移，轨迹很顺但"看不到噪声" |

### 3.2 噪声与速度读数的关系（重要）

步行一步只走 0.68 米（1.35 m/s × 0.5s），而噪声有 2 米 —— **信噪比接近 1**。
这会带来一个无法回避的数学后果：

> 相邻两点的位移 = 真实位移 + 噪声差。当噪声与真实位移同量级时，
> 位移的**期望值会被系统性抬高**（莱斯分布：|真值向量 + 噪声向量| 的期望大于真值）。

实测（4.9 公里步行轨迹，6589 个点）：

| 噪声 sigma | 速度读数均值（真值 1.35） | 速度标准差 | 最大读数 |
| --- | --- | --- | --- |
| 1.0 m | 1.39 | 0.31 | 2.42 |
| **2.0 m** | **1.48** | **0.52** | **3.38** |
| 2.5 m | 1.55 | 0.59 | 3.85 |

**这不是 bug，是物理。** 真实手机上步行时的速度读数同样有这种散布。
本工具的处理方式是：

- **`speed` 字段跟随噪声后的坐标**（`speed = 位移 / 时间`）—— 保证「拿两个坐标反推速度」和
  `speed` 字段一致，这是目标 App 最常用的检测手段；
- **`bearing` 字段不走噪声坐标**，而是用路径方向 —— 因为步行时噪声会把方向完全淹没
  （实测相邻方位角中位跳变 30°、最大 179°），而真实设备的航向是强平滑量（多普勒/卡尔曼）。

### 3.3 怎么选噪声大小

| 场景 | 建议 `--noise` |
| --- | --- |
| 只想让轨迹"看起来自然"，不追求严格一致 | 1.0 ~ 2.0 |
| **默认推荐**（城市开阔地） | **2.0** |
| 城市高楼/树荫（真实环境） | 3.0 ~ 5.0 |
| 想模拟信号差的场景 | 6.0 ~ 10.0 |
| 完全不要噪声（用于算法回归测试） | 0（并加 `--noise-alpha` 无所谓） |

```powershell
# 城市峡谷：噪声更大，精度上报也更差
python tools\mroute.py gen --preset walk --noise 5 --acc-mean 12 `
    --from ... --to ... --out out\urban.json
```

## 四、让轨迹更平滑的几种手段

按效果从强到弱：

| 手段 | 命令 | 效果 | 代价 |
| --- | --- | --- | --- |
| 减小采样间隔 | `--interval 250` | 最有效。点更密，视觉上完全平滑 | 文件变大、点数翻倍 |
| 调高噪声相关性 | `--noise-alpha 0.995` | 噪声变成缓慢漂移而非抖动 | 噪声"看不见"了 |
| 减小噪声 | `--noise 1.0` | 噪声小自然平滑 | 真实性下降 |
| 减小加速度 | `--accel 0.15` | 起步/停步更柔和 | 过小会显得"飘" |
| 抽稀路径 | 无需手动 | 生成时已做 2m 容差抽稀 | — |

**最推荐的组合**：步行默认参数（500ms）已经足够平滑。若文件大小不是问题：

```powershell
python tools\mroute.py gen --preset walk --interval 250 `
    --from ... --to ... --out out\smooth.json
```

> 4.9 公里 / 500ms → 6589 点 / 625 KB。改成 250ms 会变成约 13000 点 / 1.2 MB。
> 设备端能轻松处理（实测 6589 点回放正常）。

## 五、回放控制

```powershell
powershell -ExecutionPolicy Bypass -File scripts\mroute.ps1 play --route out\walk.json
```

| 命令 | 作用 |
| --- | --- |
| `play --route X` | 推到手机并开始走（默认等它走完，Ctrl+C 可中断） |
| `play --route X --no-wait` | 发完就返回，不等 |
| `play --route X --mult 10` | 10 倍速（走 55 分钟的轨迹 5.5 分钟看完） |
| `play --route X --mode loop` | 循环走 |
| `play --route X --direct` | 直推模式（PC 逐点广播，仅调试用，慢） |
| `mult 5` | 运行中调速 |
| `pause` / `resume` | 暂停 / 恢复 |
| `status` | 查进度（点数、当前坐标、当前速度） |
| `stop` | 停止并移除 mock 定位 |
| `logs` | 实时看手机端日志（排障用） |

> **倍速只改回放节奏，不改轨迹里的 `speed` 字段。** 想让速度值也变快，得重新生成：
> `--speed 2.7`。

一条 4.9 公里的轨迹按真实步速要走 **55 分钟**。测试时建议 `--mult 20`：

```powershell
scripts\mroute.ps1 play --route out\walk.json --mult 20 --no-wait
```

## 六、校验：怎么判断轨迹质量

### 6.1 看图

```powershell
python tools\plot-route.py out\walk.json -o out\walk.png
```

![示例](../out/walk.png)

看三件事：
1. **形状**是否沿着道路（有直角转弯是正常的，说明用的是真实路网）
2. **颜色**是否均匀（步行的速度变化小，整体应该是同一种颜色；起点略偏蓝）
3. 有没有**异常直线**或**明显折返**

### 6.2 看数值

```powershell
python tools\mroute.py show --route out\walk.json --head 3
```

输出摘要：

```
点数=6589  时长=3294.0s  沿路径里程=4943m  直线距离=3246m
速度 平均=1.50  最大=3.40  最小=0.00 m/s
范围 lat 39.881870~39.908692  lon 116.396843~116.414560
模式=once  来源=osrm(...) 路网4508m/365s 2 个途经点；抽稀 100→26 点
```

关键看：
- **沿路径里程** vs **直线距离**：差得越多说明越绕路（正常，真实道路就是绕的）
- **速度范围**：步行应落在 0 ~ 3.5 之间；最大超过 6 就有问题
- **点数×interval ≈ 时长**：不相等说明时间轴有问题

### 6.3 用现成的检查脚本

```powershell
python -m unittest discover -s tests -t . -v
```

69 项自检覆盖了坐标系、速度剖面、噪声相关性、字段自洽、CLI 行为。

## 七、参数速查表

### 路径规划

| 参数 | 说明 | 步行建议 |
| --- | --- | --- |
| `--from` / `--to` | 起终点 `纬度,经度`（WGS-84） | — |
| `--via` | 途经点，可重复 | 需要绕经某地时用 |
| `--provider` | `osrm` / `amap` / `google` / `file` | `osrm`（免费无 key） |
| `--profile` | `driving`/`walking`/`bicycling`/`foot`/`bike` | **`foot`** |
| `--file` | 本地路径文件（txt/GeoJSON/GPX） | 不想联网时用 |
| `--coord` | 输入坐标的坐标系 | 从高德/百度复制的坐标要改成 `gcj02`/`bd09` |

> OSRM 演示服务器实际只提供 driving 轮廓，`--profile foot` 会被退回 driving。
> 要真正的人行道路网，自建 OSRM 或改用高德 `--amap-mode walking`（需 key）。

### 轨迹生成

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--preset walk` | — | 一键设好步行参数（推荐） |
| `--speed` | 1.4 | 目标速度 m/s |
| `--interval` | 1000 | 采样间隔 ms |
| `--accel` | 0.4 | 加速度上限 m/s² |
| `--noise` | 0 | GPS 误差标准差（米） |
| `--noise-alpha` | 0.99 | 误差时间相关性，越大越"粘" |
| `--acc-mean` | 8 | 上报 accuracy 均值（米） |
| `--speed-jitter` | 0.05 | 速度波动比例 |
| `--lead-in` | 3 | 起步前原地漂移点数（模拟刚锁星） |
| `--lead-in-radius` | 4.0 | 漂移半径（米） |
| `--start-offset` | 0 | 从路径起点跳过多少米 |
| `--mode` | once | `once` / `loop` / `pingpong` |
| `--seed` | 无 | 固定随机种子 → 可复现同一份轨迹 |
| `--jitter` | 0 | 【旧】白噪声抖动，新项目请用 `--noise` |

## 八、典型场景配方

### 8.1 通勤路线（4.9 公里，55 分钟）

```powershell
python tools\mroute.py gen --preset walk `
    --from 39.90870,116.39750 --to 39.88220,116.40660 `
    --provider osrm --seed 42 --out out\commute.json
python tools\plot-route.py out\commute.json -o out\commute.png
scripts\mroute.ps1 play --route out\commute.json --mult 20
```

### 8.2 原地绕圈（防止被判定为「静止」）

```powershell
# 绕一个点半径 30m 走圈，一圈 2.5 分钟（等效 1.26 m/s）
scripts\mroute.ps1 circle --at 39.9087,116.3975 --radius 30 --period 150
```

### 8.3 沿导入的 GPX 走

```powershell
# 手机/手表导出的 GPX 本身就是真实走过的路线
python tools\mroute.py gen --preset walk --provider file --file my-hike.gpx `
    --speed 1.3 --out out\hike.json
scripts\mroute.ps1 play --route out\hike.json
```

### 8.4 信号差的场景（城市高楼间）

```powershell
python tools\mroute.py gen --preset walk --noise 6 --noise-alpha 0.98 `
    --acc-mean 14 --from ... --to ... --out out\urban.json
```

### 8.5 可复现的回归测试轨迹

```powershell
# 固定 seed + 关噪声 → 每次都生成完全相同的轨迹，适合放进 CI
python tools\mroute.py gen --preset walk --noise 0 --seed 12345 `
    --from ... --to ... --out out\regression.json
```

### 8.6 循环往返走

```powershell
python tools\mroute.py gen --preset walk --mode pingpong `
    --provider file --file examples\road-to-tiantan.txt --out out\back-forth.json
scripts\mroute.ps1 play --route out\back-forth.json --mode pingpong
```

### 8.7 只想看会执行什么命令

```powershell
# 不需要装 adb、不需要连手机
python tools\mroute.py play --route out\walk.json --dry-run
```

## 九、常见问题

### 蓝点不动

```powershell
scripts\mroute.ps1 doctor
```

最常见的两个原因：appops 没授权、应用被系统冻结。见 [04-排障](04-排障.md) B/C 节。

### 地图上位置整体偏移几百米

坐标系不一致。从高德/百度复制的坐标要加 `--coord gcj02` 或 `--coord bd09`。

### 轨迹跑十几分钟就停了

EMUI/MIUI 的后台管理。做这两件事：

```powershell
scripts\mroute.ps1 doctor --fix                              # 设 standby bucket 为 active
# 再到手机：设置 → 应用 → MockRoute → 电池 → 无限制
```

### 速度读数抖得厉害

这是步行 + GPS 噪声的固有现象（见第三节）。想更平滑：

```powershell
--noise 1.0 --noise-alpha 0.995
```

或把 `--interval` 降到 250ms。

### 生成的轨迹文件太大

```powershell
--interval 1000        # 回到 1 秒一个点
```

或者抽稀路径：`--start-offset` 配合分段走。

### 声明的速度与坐标位移对不上

- **无噪声时**：不应该发生。若出现请回报，测试 `test_timeline_matches_distance` 会拦住。
- **有噪声时**：中位偏差 0%，但约 2% 的点偏差 >25% —— 这是噪声导致位移期望被抬高，
  属正常现象（见 3.2 节）。要完全一致就 `--noise 0`。

### `--preset walk` 没生效

检查是否同时显式传了同名参数 —— 显式值优先。看实际生效值：

```powershell
python tools\mroute.py gen --preset walk --provider file --file examples\road-to-tiantan.txt `
    --out out\_check.json
python tools\mroute.py show --route out\_check.json
# interval 应该是 500
```

## 十、设备端行为说明

- 定位会同时写入 `gps` 和 `network` 两个 provider（Android 12+ 还有 `fused`），
  这样无论目标 App 用哪个 API 取位置都能拿到虚拟坐标。
- 轨迹文件推送到 `/sdcard/Android/data/com.mockroute/files/route.json`，
  手机端按时间戳自己回放，**PC 之后不参与** —— 所以跑一小时也不会累积误差。
- 回放结束后定位**停在终点**不会自动恢复真实定位。要恢复请执行 `stop`。
- 手机重启后 mock provider 会被系统清理，需要重新 `play`。
