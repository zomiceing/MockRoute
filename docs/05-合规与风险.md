# 05 · 合规与风险

这份工具是**测试工具**。请先读完这一页再决定怎么用它。

---

## 一、合法用途

以下都是正当的工程需求，也是这个项目存在的理由：

- **自研 App 的位置功能回归测试** —— 不用真的跑到现场，CI 里就能跑完「进入围栏 → 上报 → 离开围栏」的用例；
- **外卖/网约车/物流类 App 的派单与轨迹算法验证** —— 需要可控的、可复现的移动轨迹；
- **地图与导航类产品的演示** —— 现场演示不能靠天吃饭；
- **竞品对比与可用性测试**；
- **隐私保护** —— 在不需要真实位置的场景下不给真实位置；
- **教学与研究** —— 演示 GPS 定位链路是如何工作的。

判断标准很简单：**你是否有权改动这台设备上这个 App 的行为？**
自己的 App、自己的设备、有授权的测试环境 → 没问题。

---

## 二、明确不要做的事

- 伪造**考勤打卡**（这是最常见的滥用场景，也是纪律处分/解除劳动合同的常见理由）；
- 伪造**运动/体能考核里程**——校园跑、体育课打卡、体测、健身积分等。
  这类 App 的里程直接换算学分/成绩，伪造它和多考了几分没有区别，
  多数高校会按**学术不端**处理（已有学生被处分的公开案例）；
- 伪造**网约车行驶轨迹**骗取平台补贴；
- 伪造**外卖/跑腿配送位置**刷单；
- 绕过**游戏地域限制、赛事定位校验**；
- 伪造位置骗取**优惠券、红包、签到奖励**；
- 向平台提交虚假位置数据以获取任何形式的利益。

这些行为可能触犯：

| 法律/规范 | 相关情形 |
| --- | --- |
| 《刑法》第 285/286 条 | 非法侵入/破坏计算机信息系统 |
| 《刑法》第 266 条 | 诈骗罪（骗取补贴、奖励） |
| 《反不正当竞争法》 | 刷单、虚假交易 |
| 《网络安全法》 | 提供专门用于从事危害网络安全活动的程序、工具 |
| 平台服务协议 | 封号、扣款、追偿，民事违约 |

**未 root 的 mock 定位方案尤其容易被抓到**，见下节。

## 三、目标 App 是怎么发现你的

这一节不是教你绕过检测，而是让你**清楚这套方案的边界**——
如果对方真的在意，未 root 的 mock provider 是藏不住的。

### 3.1 一眼可见的硬证据

```java
location.isFromMockProvider()   // Android 17 之前一直可用，mock 点必为 true
```

`Location.isMock()`（Android 12+）同理。
MockRoute **不打算**伪造这个字段：伪造它需要反射改 framework 内部数据，
在 Android 9+ 的隐藏 API 限制下会让调用方直接崩溃，而且一旦对方在 native 层读原始数据就立刻穿帮。

而且这个字段本身在 Android 17 已被移除/改变语义 —— 说明它从来不是可靠判据，
真正在意定位真实性的 App 用的是下面这些手段。

### 3.2 环境交叉验证

| 检查项 | 说明 |
| --- | --- |
| Wi-Fi BSSID / 扫描结果 | 与 GPS 坐标是否在同一区域 |
| 基站 CellID / 邻区 | 同上，且能反查大致位置 |
| 蓝牙信标 | 室内场景常用 |
| IP 归属地 | 与坐标是否矛盾 |
| 传感器融合 | 加速度计/陀螺仪/磁力计与「移动」是否一致 |
| 多 provider 一致性 | `gps` vs `network` vs `fused` 是否互相矛盾 |
| 定位时间序列 | 是否完美直线、速度是否恒定、精度是否恒定 |

MockRoute 已经在轨迹层面尽量做到自然（速度剖面有加速/刹车/波动、方位角与位移自洽、
精度随机波动、起步有锁星漂移），但**传感器和网络侧它管不了**。

### 3.3 开发者选项与系统状态

- 是否开启了「开发者选项」；
- 是否设置了「模拟位置信息应用」；
- 设备是否 root / 是否装了 Magisk / Xposed；
- 是否处于模拟器（`Build.FINGERPRINT`、传感器列表、CPU 特性都会暴露）。

未 root 方案在前两项上必然留痕。

### 3.4 结论

| 对手的检测强度 | 未 root mock 是否能过 |
| --- | --- |
| 完全不检测 | 过 |
| 只查 `isFromMockProvider` | 不过 |
| 查 mock provider + 开发者选项 | 不过 |
| 加环境交叉验证 | 不过 |
| 加传感器融合 / 行为分析 | 不过 |

**所以：把它当测试工具，不要当绕过手段。** 它能让你的测试用例跑起来，
但拦不住一个认真做风控的 App。

## 四、root / hook 方案为什么这里不提供

用 Xposed/LSPosed 或 Frida hook 掉 `LocationManager`、直接返回自造数据，
确实能绕过上面大部分检测。本项目**不提供**这类实现，原因：

1. 它的**唯一**用途就是欺骗第三方 App，正当测试需求用 mock provider 已经够了；
2. 这类代码在多数司法辖区被认定为「专门用于规避技术措施的工具」；
3. 一旦被用于前述滥用场景，作者与使用者都难以主张善意。

如果你做的是**安全研究**（例如评估某 App 的风控强度），这条路你应该自己写，
并且确保有书面授权、在隔离环境、遵守漏洞披露流程。

## 五、使用前自查

- [ ] 目标 App 是我自己的，或我拿到了书面测试授权
- [ ] 目标设备是我自己的，或属于我负责的测试机
- [ ] 我不会用输出数据去获取任何形式的利益
- [ ] 我知道这套方案会被 `isFromMockProvider()` 识破，并接受了这个边界
- [ ] 我会在测试结束后执行 `stop`，把设备定位恢复正常

如果有一条打不上勾，请先解决它。
