# 01 · 环境准备

只需要做一次。整个流程分三块：**PC 侧**（跑脚本）、**手机侧**（装 APK、开调试）、**APK 构建**（只需要一次）。

---

## 1. PC 侧

### 1.1 Python 3.8+

```powershell
python --version
```

只需要标准库，**不需要 pip install 任何东西**（没有 requests、没有 numpy）。3.8 以上均可，本项目在 3.11 上验证。

### 1.2 adb（Android SDK Platform-Tools）

这是 PC 与手机之间唯一的通道。

三种拿到方式，任选其一：

**A. 已经有 Android Studio** —— 直接用自带的：
```
%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe
```

**B. 只想要 adb** —— 下载 Platform-Tools 压缩包，解压后把目录加进 PATH：
<https://developer.android.com/tools/releases/platform-tools>

**C. 让脚本帮你装** —— 跑 `scripts/setup-android.ps1`，它会连 SDK 一起装好（见第 3 节）。

验证：

```powershell
adb version
```

脚本找不到 adb 时也可以显式指定：

```powershell
python tools/mroute.py doctor --adb "D:\Android\Sdk\platform-tools\adb.exe"
```

## 2. 手机侧

### 2.1 打开开发者选项

设置 → 关于手机 → 连续点「版本号」7 次。

> 国产 ROM 路径略有差异：小米在「设置 → 我的设备 → 全部参数 → MIUI 版本」连点；
> 华为/荣耀在「设置 → 关于手机」连点「版本号」；OPPO/vivo 类似。

### 2.2 打开 USB 调试

设置 → 系统 → 开发者选项 → **USB 调试** 打开。

小米还需要额外打开「**USB 调试（安全设置）**」，否则 `appops` 授权和广播可能被拦。

### 2.3 连接并授权

插上 USB 线（**必须是数据线**，纯充电线不行），手机会弹出「允许 USB 调试吗？」——勾选「一律允许」并确定。

```powershell
adb devices
```

必须看到：

```
List of devices attached
ABCD1234        device
```

如果显示 `unauthorized`，说明手机上的弹窗没点允许（或点了拒绝）：
开发者选项 → 撤销 USB 调试授权 → 重新插线。

如果列表为空：

- 换一根线、换一个 USB 口（优先主板后置口，别用前面板或 hub）；
- 部分 ROM 需要在「开发者选项 → 默认 USB 配置」里选「传输文件」；
- 华为/荣耀在「开发者选项」里还有「仅充电模式下允许 ADB 调试」，要打开。

### 2.4 关掉会捣乱的东西

| 设置 | 为什么 |
| --- | --- |
| 电池优化 → MockRoute 设为「无限制」 | 否则长轨迹跑到一半会被冻结 |
| 开发者选项 → 「不锁定屏幕」 | 调试时省事；锁屏后部分 ROM 会限制后台 |
| 关闭「自动切换网络/GPS 节能」类开关 | 有些 ROM 会强制走网络定位，覆盖 mock |

## 3. 构建 APK

**如果别人已经给了你 `app-debug.apk`，直接跳到第 4 节。**

### 3.1 一键脚本（推荐）

```powershell
# ① 装工具链（JDK + Android SDK + Gradle，约 400MB）
powershell -ExecutionPolicy Bypass -File scripts/setup-android.ps1 `
    -SdkRoot .toolchain\android-sdk

# ② 构建 + 安装 + 授权 + 启动（一条命令走完）
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Install -Launch
```

之后所有 mroute 命令都走包装脚本（它负责配好 adb/JDK/Gradle 所需的环境变量）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/mroute.ps1 doctor
powershell -ExecutionPolicy Bypass -File scripts/mroute.ps1 point --at 39.9087,116.3975
powershell -ExecutionPolicy Bypass -File scripts/mroute.ps1 play --route out\demo.json
```

#### 为什么需要 `prep-build.ps1` 这层「镜像构建目录」

如果你的仓库路径含非 ASCII 字符（例如 `—` em dash、中文目录名），Windows 上
AGP/Gradle **无法**在这种路径下构建：

- Gradle daemon 创建项目 `.gradle` 目录时会把路径里的非 ASCII 字符弄乱，报
  `Failed to create parent directory ...\.gradle`；
- 即便建成功，AGP 也会直接拒绝：`Your project path contains non-ASCII characters`。

**用目录联接（junction）无效** —— JVM 会把链接解析回真实（非 ASCII）路径，照旧失败。

所以 `prep-build.ps1` 把 Android 工程镜像到工作区**内部**的一个纯 ASCII 目录
（`build-ws/`，必须在工作区内，因为沙箱只允许写那里），在那里构建，再把 APK 拷回
`dist/MockRoute-debug.apk`。`build-android.ps1` 会自动调用它。

> 每次改完源码不用手动做什么：`build-android.ps1` 的「源码再同步」会把 `app/`、
> `build.gradle.kts`、`settings.gradle.kts` 刷新过去。但**它刻意不同步
> `gradle.properties` 和 `local.properties`** —— 这两个是 `prep-build.ps1` 生成的，
> 里面带着 `android.overridePathCheck=true` 和 `\u` 转义过的 `sdk.dir`。
> 覆盖它们会让上面的绕行失效。

脚本参数：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-android.ps1 -SkipDownload   # 已装好，只做配置
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Refresh        # 强制重新镜像
powershell -ExecutionPolicy Bypass -File scripts/build-android.ps1 -Clean          # 清理后重建
```

> **关于 `-ExecutionPolicy Bypass`**：Windows 默认禁止运行 `.ps1`（报
> 「因为在此系统上禁止运行脚本」）。这种写法只对这一次调用生效，不改系统策略。
> 装了 PowerShell 7（`pwsh`）的话换成 `pwsh -NoProfile -File` 即可。
>
> **所有脚本都是纯 ASCII 的**，因为 Windows PowerShell 5.1 在没有 UTF-8 BOM 时按
> ANSI 读文件，中文注释会变乱码甚至破坏解析。中文说明一律放在 `docs/` 里。
>
> **下载走 `tools/fetch.py`（Python + OpenSSL）**，不用 `Invoke-WebRequest`。
> 原因见 [04-排障](04-排障.md) 的「TLS 握手失败」一节。
> 同理，`sdkmanager` 在部分机器上会卡死，所以 SDK 组件由
> `tools/sdk-direct.py` 直接下载官方 zip 落位（它处理了 `build-tools_r34` 压缩包
> 内部顶层目录叫 `android-14`、必须改名成 `34.0.0` 这个坑）。

### 3.2 用 Android Studio（最稳）

1. Android Studio → Open → 选 `mockroute-android/` 目录
2. 等 Gradle Sync 完成（它可能提示升级 AGP，可以拒绝）
3. Run ▶ 或 Build → Build APK(s)

### 3.3 纯命令行

```powershell
cd mockroute-android
.\gradlew.bat assembleDebug
# 产物：app\build\outputs\apk\debug\app-debug.apk
```

没有 wrapper 时用系统 gradle：

```powershell
gradle assembleDebug
```

要求：**JDK 17**（AGP 8.x 不支持 JDK 8/11）、Gradle 8.x。

### 3.4 手动安装

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## 4. 授予模拟位置权限（**最关键的一步**）

未 root 设备上，只有被系统认定为「模拟位置信息应用」的 App 才能写入定位。
没有这一步，广播会「成功」但定位完全不动。

**方式 A：命令行（推荐，可脚本化）**

```powershell
adb shell appops set com.mockroute android:mock_location allow
adb shell appops get com.mockroute android:mock_location
# 期望输出包含：android:mock_location: allow
```

**方式 B：手动点**

设置 → 系统 → 开发者选项 → **选择模拟位置信息应用** → 选 **MockRoute**。

> 如果列表里看不到 MockRoute，先把 App 启动一次再回来看。
> Android 12+ 上这个选项可能在「开发者选项 → 模拟位置信息应用」二级菜单里。

### 验证

```powershell
python tools/mroute.py doctor
```

期望最后一行是「环境就绪」。`doctor --fix` 会直接帮你执行 appops 授权。

## 5. 目录准备

MockRoute 用应用私有外部目录存放轨迹文件，PC 可以免权限直接写入：

```
/sdcard/Android/data/com.mockroute/files/
```

**这个目录在 App 第一次启动后才会被系统创建。** 所以：

```powershell
adb shell am start -n com.mockroute/.MainActivity
```

在手机上看到 MockRoute 面板（显示自检信息）就说明目录已就绪。`doctor` 也会检查目录可写性。
