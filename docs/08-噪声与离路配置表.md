# GPS 噪声与离路距离 · 配置表

由 `python tools/noise-table.py --csv out/noise-table.csv` 实测生成。
基准路径：`examples/road-to-tiantan.txt`（真实道路 4673 m）。

## 三个指标怎么看

| 指标 | 含义 | 健康范围 |
| --- | --- | --- |
| **离路** | 上报坐标到路径的距离（中位 / 90分位 / 最大） | 按你的要求定 |
| **被夹** | 落在离路上限附近的点占比 | **<3%**；>10% 说明误差分布退化成一个圆 |
| **速度偏差** | 上报速度相对目标速度的偏差 | <10%；σ 越大越偏高 |

「被夹」为什么重要：真实 GPS 的误差是连续的（Rayleigh 分布），不会有一堆点
正好落在同一半径上。夹太多就是可被检测的痕迹。

「速度偏差」为什么重要：噪声会把上报速度**系统性抬高**（位移里混进了噪声分量）。
σ=3.0 时实测偏高 **24%** —— 那是「走路报成了慢跑」的量级。

## 三、推荐组合（可直接抄）

```powershell
# ① 最通用：普通街道步行，贴路 3m 内，分布自然
--noise 1.5 --max-offset 3

# ② 贴路 1m 内，且分布不退化（要同时降噪声 + 加密采样）
--noise 0.5 --max-offset 1 --interval 250

# ③ 城市跑步
--noise 2.0 --max-offset 3

# ④ 开阔地（操场、江边），最自然
--noise 0.5 --max-offset 2

# ⑤ 密集城区：噪声必然大，别硬压上限（会退化）
--noise 3.0 --max-offset 8
```

## 四、三个陷阱

**① 只压上限、不降噪声 → 分布退化。**
σ=1.5 配上限 1m，被夹 13.3%，一堆点正好落在 1.00m 上。真实 GPS 不会这样。

**② 忘了速度偏差。**
σ=3.0 时上报速度偏高 24%。如果你设的目标速度是 1.35 m/s，实际会报成 1.68。
要么接受，要么用 `--speed` 往下调一点补偿。

**③ 物理下限约 0.9 米（与 σ 无关）。**
那是**均匀采样的离散误差**：一步跨过弯道时，直线插值偏离真实路径的量，
与 GPS 无关。想压下去只能加密采样（`--interval 250`，误差减半）。
